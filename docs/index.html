Safety and evidence

Know what was checked.

A passing command is useful evidence, not a guarantee of production safety. Every run reports its scope, findings, checks, and delivery status.

Isolated attempts
Each package starts from committed HEAD in a separate worktree. Failures discard that attempt. Staged, unstaged, and untracked work in your checkout is excluded and preserved. Only run trusted project code.
Conservative version selection
A candidate must be outside every supported advisory range. Unknown ranges, unfixed advisories, and prereleases remain visible for manual review.
Baseline, checks, rescan
Verify the original project first. After updating persistent dependency files, run all configured checks and confirm the target version with OSV. Scanner errors never mean clean.
Reviewable delivery
Keep a local commit or create a draft PR with evidence. No forced push, merge, or deployment. Independent fixes require integration testing before combining them.
Current coverage

Scan broadly. Automate supported updates.

OSV scans nested manifests. Automatic updates cover unambiguous Node dependencies and declared workspaces, guarded transitive overrides, and plain, exactly pinned Python requirements.txt files. Dependency categories are preserved.

Ambiguous workspace ownership, existing override policies, peer dependencies, managed Python lockfiles, Go, Rust, Java, .NET, and submodules need manual repair. Unsupported findings remain in the report. Node lifecycle scripts are disabled during installs. Workspace verification runs required root checks and available owner checks in their respective directories.

Both Node typecheck and test scripts run when available. Python uses a private temporary environment. You can specify additional trusted test commands. Git worktrees are not a security sandbox for untrusted code.

First run

Point GreenPR at your project.

Install Python 3.11+, Git, OSV-Scanner v2, and your project's package manager. Clone GreenPR separately from the project you want to inspect.

git clone https://github.com/tech49labs/greenpr.git /path/to/greenpr
python -m pip install -r /path/to/greenpr/requirements.txt

# Use your own project path:
python /path/to/greenpr/remediate.py --repo /path/to/your-project --preflight
python /path/to/greenpr/remediate.py --repo /path/to/your-project --dry-run

# Create reviewed local branches without pushing:
python /path/to/greenpr/remediate.py --repo /path/to/your-project --skip-pr

Use a virtual environment for GreenPR. Preflight executes no project code. Dry runs scan committed HEAD and exit 2 when findings exist. A JSON evidence report is written outside the target repository. Exit 1 means failed or incomplete work.
