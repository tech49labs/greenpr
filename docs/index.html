Local quickstart

Start with a scan.

Install GreenPR separately, then run it from the repository you want to inspect.

Follow the setup guide to install the required tools. GreenPR verifies updates in a separate worktree; use a dedicated runner for untrusted project scripts.

Read the setup guide ↗ 
# From the GreenPR tool directory
python -m venv .venv
# Activate the environment, then:
python -m pip install -r requirements.txt

# Change into the repository to inspect
cd /path/to/your/repository
python /path/to/greenpr/remediate.py --scan-only

# Verify one update in a review worktree
python /path/to/greenpr/remediate.py --test-cmd "npm test" --skip-pr
Before you start

Clear boundaries. Fewer surprises.

Does GreenPR send code to a model provider?

Model-assisted repair is opt-in. When enabled, candidate source files and error traces may be sent to your configured provider. Dependency updates and verification do not require model repair.

What happens when checks fail?

A failed baseline stops the run. Remediation runs in a separate worktree. If an update fails verification, no pull request is published and your original checkout remains unchanged. Package installs and tests can still have effects outside Git, so use a dedicated runner.

Which projects can I use it with?

Adapter coverage varies by ecosystem. Start with one dependency and validate the manifest, lockfile, installed version, and checks. The README documents the release scope and limitations.

Where does GreenPR run?

GreenPR runs on infrastructure you control. No hosted account is required to evaluate the runner. Model usage and CI compute, if you choose them, are billed separately by those providers. GreenPR does not merge or deploy your application.
