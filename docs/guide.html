Setup guide

From repository
to reviewed update.

Run GreenPR on infrastructure you control. Start with a scan, inspect one update, and choose what to merge.

Community use is free for public open-source repositories and local personal evaluation. No account or payment details are needed to get started.

Set up once. Let your CI run it.

GreenPR is a command-line tool with an optional GitHub Action, not a hosted repository connection service. Set it up once on your runner, choose your project's checks, and let your existing CI schedule start each run.

Each run checks the unchanged project first, updates a dependency, then repeats those checks. Both must pass before GreenPR publishes a pull request. Your team reviews the changes and decides whether to merge. GreenPR does not automatically merge them.

Use the scheduled GitHub Actions example as a starting point. Adapt its runner, package-manager prerequisites, permissions, and test command to your repository. The example uses a local action for GreenPR's own repository; in yours, reference GreenPR at a trusted, reviewed full commit SHA. The steps below show a manual first run so you can review its behavior before scheduling it.

1. Install the prerequisites

Use Python 3.11 or later, Git, OSV-Scanner v2.7.0, and the package manager used by your repository. Publishing pull requests also requires the authenticated GitHub CLI and a configured Git author name and email on your runner. Use a dedicated runner: package managers and verification commands execute repository code.

2. Install GreenPR separately

Keep the tool outside the project you want to maintain. Your project folder contains the application; the separate GreenPR folder contains the tool. Use the complete Windows PowerShell or Linux first-run commands for a checksum-verified scanner installation and paths that work with spaces. Community scanning and local evaluation require no GreenPR account, payment details, license file or model API key.

Linux installation, after installing the prerequisites:

git clone https://github.com/tech49labs/greenpr.git
cd greenpr
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt

On Windows, follow the PowerShell installation in the linked first-run guide, then call the virtual environment directly without activating it:

& 'C:\tools\greenpr\.venv\Scripts\python.exe' 'C:\tools\greenpr\remediate.py' --help

Save your project's checks once

You can keep the project directory, required checks, and test prerequisites in a reviewed .greenpr.toml file at the repository root. For example:

version = 1
project = "."
gates = ["npm test", "npm run typecheck"]
executables = ["node", "npm"]
required_env = ["NODE_ENV"]
setup = []
cleanup = []
timeout_seconds = 300
services = []

[environment]
NODE_ENV = "test"

Every gate must pass; there is no weaker fallback. Put only non-secret test defaults in environment. Do not copy production environment files or credentials into the configuration. Required environment entries contain variable names, not their values. Optional services name local test endpoints such as 127.0.0.1:5432.

Explicit setup commands run only in the separate review worktree before verification. They may initialize test fixtures or invoke your reviewed test container, and a failed setup stops the run. Review these commands like other repository code: isolation of files does not prevent commands from accessing the network or external services. Configure test services and containers to use disposable data, then include their actual checks in the required gates.

Set timeout_seconds to a whole number from 1 to 7200 for your configured commands. Optional cleanup commands release only the disposable services owned by that run; GreenPR does not add generic cleanup commands. Use the supplied unique GREENPR_RUN_ID to name your test containers or Compose project. Do not share a production service or use global prune commands. Container gates must rebuild or synchronize the current candidate source and lockfile every time they run, so the post-update checks exercise the changed dependency.

After saving the configuration, run python /path/to/greenpr/remediate.py --doctor from the repository root to check prerequisites without installing or changing files. Additional --test-cmd arguments add checks; they do not replace configured gates.

3. Scan your repository

Change into the target repository and use the GreenPR virtual-environment interpreter. The linked first-run guide includes exact PowerShell commands. Linux example:

cd /path/to/your/repository
/path/to/greenpr/.venv/bin/python /path/to/greenpr/remediate.py --scan-only

Scan-only does not install dependencies, run your verification commands, or call a model. Scanning contacts advisory services and, where needed, package registries to verify dependency versions. If the scanner cannot complete, GreenPR reports an error rather than treating missing evidence as a clean result.

4. Verify an update

Start from a clean Git checkout with your changes committed. GreenPR processes one dependency update per run. For an npm project, start with:

/path/to/greenpr/.venv/bin/python /path/to/greenpr/remediate.py --test-cmd "npm test" --skip-pr

Choose commands that cover all checks required by your project. To require more than one command, repeat the option:

/path/to/greenpr/.venv/bin/python /path/to/greenpr/remediate.py --test-cmd "npm test" --test-cmd "npm run typecheck" --skip-pr

All selected commands must pass before and after the update. If you omit the override, GreenPR discovers the supported verification scripts in the project. It does not replace a failed test suite with a weaker passing check.

For a separate project in a monorepo, add --project path/to/project and select its verification commands. Each remediation run targets one project ecosystem. Use --scan-only --ecosystem all to inspect multiple ecosystems without changing dependencies.

5. Review the result

When publishing against a reviewed branch other than the repository default, add --base-branch your-review-branch. Make sure that branch already exists on GitHub and represents the intended comparison point. GreenPR validates the branch name before setup and records it in the receipt. This option does not change or bypass any verification gate.

Remediation runs in a separate Git worktree. With --skip-pr, GreenPR retains the review worktree and writes a patch and JSON receipt. The original checkout remains unchanged. Inspect the reported paths, manifest and lockfile changes, installed dependency version, and verification results before merging.

The tested npm path includes root projects and npm workspaces. Read the repository documentation for the current adapter acceptance and command options. A successful verification command is evidence of those checks, not a guarantee about every behavior in your application.

Commercial repository licensing

Team costs $49 USD per repository per month. Enterprise costs $899 USD per organization per month. Request a GreenPR plan with your company name, contact name, email and optional contact details. No sign-in is required. Your enquiry is private; we will contact you about the selected plan. The form does not take payment. Do not include credentials, payment details, private repository links, source code or signed licenses.

Commercial licenses can be issued for offline verification. When GreenPR provides your signed license file, store it securely and configure GREENPR_LICENSE_FILE with its path. Then use --commercial for commercial runs. Do not edit the signed file or commit it to a public repository.

Optional model-assisted repair

Scanning and verified dependency updates need no model key. Optional AI repair uses your own key, chosen supported provider and explicit model ID. Follow the BYOK setup guide. Repair is disabled by default; enabling --enable-model-repair can send candidate source files and error traces to that provider. Use a provider approved for the repository. Live AI repair is experimental; offline routing tests do not establish model availability or repair quality. Provider usage is billed by your provider. Every proposed change still has to pass the project's verification gates.

Get help

Contact GreenPR support through GitHub with your environment and a sanitized error. A GitHub account is required, and requests are public. Remove private paths and repository details from commands and logs. Never post tokens, API keys, payment details, signed license files, or private source code.
